# REPORT — 融合深化⑨:效率基准("可验证 AND 低能耗"实测)

**日期**: 2026-06-20 | **复现**: `.venv/bin/python experiments/fusion_benchmark/run.py`

## 0. 一句话
定位的联合主张不只是"可验证",而是"**验证还便宜且确定**":精确 do()+IPRG 凭证亚毫秒、全凭证认知周期亚毫秒,远超蓝图 100ms/10周期每秒目标。

## 1. 结果(自检 PASS,CPU)
| 操作 | 延迟 | 可验证 |
|---|---|---|
| 精确 do() + IPRG 凭证(含 pgmpy 复算) | **0.458 ms** | yes |
| 签名记忆召回 | 0.012 ms | yes |
| 沙盒动作门 | 0.006 ms | yes |
| **全凭证周期(3 层)** | **0.487 ms** | yes |
| 吞吐 | **~2054 周期/秒** | — |

## 2. 含义
- **可验证 ≠ 昂贵**:凭证机制亚毫秒、确定性(同输入→同输出→同凭证),vs LLM 花数千 token 去近似同一个 do()(且过组合悬崖后常错)。
- 远超蓝图"10 周期/秒、<100ms"目标(实测 ~2000 周期/秒、<0.5ms)。
- 这是"可验证+低能耗"联合主张的实测落地,呼应论文效率论点(引擎近零成本 vs LLM 千 token 浪费)。

## 3. 诚实边界
- 离散小图;大图/高 treewidth do() 会更慢(精确边缘化指数),但这正是变量消元/塌缩(探针2)与悬崖刻画的对象。
- 测的是延迟非能耗瓦数,但延迟+确定性已强支撑"低成本可验证"对比。
