# REPORT — 主权记忆柱：因果签名检索 vs 表面相似检索（真实 embedding 验证）

**日期**: 2026-06-17 | **柱**: 主权持久记忆（The One 第二支柱）| **真实 OpenAI embedding** | **真实度**:【已验证·真实 embedding·最小语料】
**复现**: `source ~/.theone_keys.env && .venv/bin/python experiments/memory_real_embedding/run.py`
**前置**: `experiments/memory_causal_cliff/`（仿真版，凭证与关联均为标量）

## 0. 一句话
把仿真发现升级到真实 embedding（`text-embedding-3-small`）：**凭证（因果签名）检索免疫混杂的结论完全复现**——误差恒在凭证噪声地板（≈0.07–0.16），与混杂 σ 无关；**扁平相似检索系统性失败的结论也复现，且更强**——真实 embedding 不仅在混杂下捞错，连 σ=0 都捞错（MAE 0.77，仿真里 σ=0 扁平本是 0.01 的赢家）。原因诚实可诊断:真实文本 embedding 把不相关词项（治疗名/病房名）和被粗粒度量化的效应措辞混在一起，连"表面关联 a"都没干净恢复。

## 1. 设置（最小真实语料）
每条记忆=一次过去干预的临床笔记文本，模板统一为「某治疗 在 某环境 实施；随访结果 {量化措辞} 相对基线」。
- **真因果效应** c ~ U(-2,2)（后门调整后，去混杂）。
- **观测/混杂效应** a = c + N(0,σ)；**措辞只描述 a**（分箱成 negligibly/slightly/moderately/substantially/dramatically × improved/worsened），文本不泄露 c。
- **凭证签名** ĉ_q = c_q + N(0,0.10)（如 Pillar 1 去混杂计算的产物，带凭证噪声，out-of-band）。
- 每条文本经真实 OpenAI `text-embedding-3-small` 求向量（带磁盘缓存 + ≤50 次 API 预算守卫；本次共 12 次批量调用，重跑 0 次）。

检索（top-1，迁移其 c，误差=|c_retrieved − c_q|）：
- **扁平检索**：query 文本 embedding 与库 embedding 的 **cosine 最大**者（真实表面相似）。
- **凭证检索**：|c − ĉ_q| 最小者（去混杂签名匹配）。
- **oracle-a（诊断列）**：按真实标量 a 最近匹配——即仿真假定扁平检索能达到的"干净关联"基线。

规模：库 M=24，每个混杂档 6 个 query，σ ∈ {0, 0.25, 0.5, 1.0, 1.5, 2.0}。

## 3. 是否复现仿真发现
**复现，且其中一半比仿真更强：**
1. **凭证检索免疫混杂 —— 完全复现。** 凭证 MAE 在所有 σ 上都贴着凭证噪声地板（0.069–0.164，无随 σ 的趋势），正是仿真里的"恒为 0.079 地板、与混杂无关"。这是核心机制，真实 embedding 下原封不动成立——因为凭证检索压根不碰 embedding，用的是去混杂签名。
2. **扁平检索失败 —— 复现且更强。** 仿真里扁平在 σ=0 是赢家（关联=因果，0.01），随 σ↑ 才退化（→1.13）。真实 embedding 下扁平 **全程失败**（0.77–1.36，扁平/凭证 6–20×），σ=0 也照样糟。
3. **诊断列解释了为什么"更强"。** oracle-a（干净标量关联）严格复现仿真形状：σ=0 时 0.057（好），随 σ↑ 单调升到 1.69——这正是"关联随混杂脱钩因果"的仿真曲线。真实 embedding 扁平在低 σ **还差于** oracle-a（0.77 vs 0.057），说明真实文本 embedding 连"表面关联 a"都没干净恢复:统一模板里的治疗名/病房名等无关词项，叠加效应措辞的粗粒度分箱（同一句"moderately improved"对应一段 a 值），让 cosine 频繁捞出符号都相反的记忆（见 results.json，σ=0 的 q2：query"slightly worsened"却检索到 a=+1.61 的记忆）。

**一句话**:仿真把扁平检索理想化成"按干净标量关联排序"；真实 embedding 比这更糟。但被验证的核心科学主张——**"因果签名检索可验证地正确、免疫混杂；表面相似检索捞错记忆迁移错效应"——在真实 embedding 下成立且裕度更大**。

## 4. 跨柱统一
凭证检索免疫混杂的真实-embedding 证据，与仿真同义:凭证（Pillar 1 去混杂计算的产物）让记忆柱（Pillar 2）的因果迁移可验证正确，正确性继承自计算柱、由凭证质量（可控）而非混杂或 embedding 噪声（不可控的表面属性）决定。真实 embedding 只是把"表面属性不可控"这件事演示得更直白——它连表面关联都不可控。

## 5. 诚实边界
- **语料是合成的、最小的**：M=24、6 query/档、单一临床模板。文本由模板生成，不是自然语料；结论是"机制在真实 embedding 下成立"，不是"在任意真实文档分布上的效应量"。effect 措辞的分箱是人为选择，换分箱粒度会改变 oracle-a 与扁平的绝对数值（但不改变定性结论:凭证恒平、扁平随混杂/粗粒度失败）。
- **embedding 真实，但只测了一个模型一个版本**（`text-embedding-3-small`）。更大模型或专门微调的检索器或许能更好地从措辞恢复 a——但那只会把扁平拉近 oracle-a 基线，仍受混杂脱钩的根本限制（σ↑ 时 oracle-a 本身就败）。
- **扁平"全程失败"部分是模板伪影**：统一模板让无关词项占了 cosine 的大头。这恰恰是真实记忆检索的真实风险（语义相似≠因果相似），但它放大了 σ=0 的扁平劣势，读者不应把"σ=0 扁平 0.77"当成纯混杂效应——σ=0 的劣势主要来自 embedding 粗粒度，混杂效应见 σ>0 的 oracle-a 单调上升。
- **凭证仍是注入的**:ĉ_q 是带 0.10 噪声的去混杂签名，不是从文本里学出来的。本实验验证的是"若有凭证，签名检索免疫混杂"，不验证"如何从文本产出凭证"（那是计算柱的事）。
- 非完整记忆系统:无持久化（仅 embedding 磁盘缓存供续跑）、无向量库、无主权层、无规模检索。bounded 验证，点亮一个机制。

## 6. 结论
真实 embedding 验证通过:**因果签名（凭证）检索免疫混杂、表面相似（真实 cosine）检索系统性捞错** 在 `text-embedding-3-small` 下复现——凭证恒在噪声地板，扁平全程 6–20× 更差。最大诚实警告:语料是合成最小模板、扁平在 σ=0 的劣势部分来自真实 embedding 对效应量级的粗粒度而非纯混杂（诊断列 oracle-a 把二者分离）。记忆柱的核心价值主张——"在因果决策需要小心的混杂 regime，可验证地正确"——从仿真前进到了真实 embedding 证据。
