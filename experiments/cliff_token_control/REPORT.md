# REPORT — token 长度混杂对照：悬崖是边缘化负荷(2ᵏ)，不是上下文长度

**日期**: 2026-06-16 | **依据**: NOTE-018（NOTE-006/017 续）| **触发**: 外审 MML 推理研究者的最尖锐攻击
**复现**: `python experiments/cliff_token_control/{run.py,run_deepseek.py,run_gemini.py}`

## 0. 一句话
外审专家指出"组合悬崖"唯一须排除的混杂：k 增大时 prompt 也变长，崩溃会不会其实是 **long-context 退化 / 中间步骤算错**（那篇 *frontier LLMs still struggle with simple reasoning* 的警告），而非"精确边缘化不可终止"本身。我们用**孤立干扰根变量**把"prompt 长度"和"边缘化负荷 2ᵏ"解耦——结果：**长度被控制、甚至反转，悬崖照崩**。在干净被试 gpt-5.1 上完全成立；跨家族负荷敏感性也复现。

## 1. 设计：孤立干扰变量解耦长度与负荷
对一道 k 个混杂的题，追加 d 个**孤立干扰根变量** D₀..D_{d-1}：每个只加一行 `P(Dᵢ)=...`（增加 token），但**不指向 X 或 Y**，因此对 `P(Y|do(X))` 及其要边缘化的 2ᵏ 项**毫无影响**。于是可单独把 prompt 拧长而难度不变。

- **定长扫描**：固定 k=2（负荷=4），变 d → prompt 变长、负荷不变。若准确率不掉，长度非主因。
- **杀手对照**：低负荷长 prompt vs 高负荷短 prompt。若长的满分、短的崩溃，则凶手是 2ᵏ，不是长度。

引擎在所有格子精确（真值 = 独立概率引擎逐位计算），故"中间步骤算错"那条也被压住：崩的是模型，不是题目没确定解。

## 2. gpt-5.1（干净被试）：长度被控制甚至反转，悬崖照崩 ✅
| 格子 | prompt 词数 | 2ᵏ 负荷 | 准确率(±.005) |
|---|---|---|---|
| 定长 k2 d0 | 66 | 4 | **1.00** |
| 定长 k2 d10 | 76 | 4 | **1.00** |
| 定长 k2 d25 | 91 | 4 | **1.00** |
| 定长 k2 d45 | 111 | 4 | **1.00** |
| 负荷 k4 d0 | 120 | 16 | 0.60 |
| 负荷 k5 d0 | 177 | 32 | **0.00** |
| **杀手·k2 d120(最长,低负荷)** | **186** | 4 | **1.00** |
| **杀手·k5 d0(更短,高负荷)** | 177 | 32 | **0.00** |

**读法**：① 定长扫描——prompt 66→111 词、负荷锁死=4，准确率纹丝不动 1.00（长度单独零效应）。② 负荷扫描——4→16→32，准确率 1.00→0.60→0.00。③ **杀手对照——186 词（最长）满分，177 词（更短）归零**。长度不仅被控制、还被反转，崩溃精确跟着 2ᵏ 走。**专家判据"控住 token 长度还能看到 cliff"达成。**

## 3. deepseek-v4-flash（跨家族，诚实结果）：负荷复现，但非干净被试 ⚠️
| 格子 | prompt 词数 | 2ᵏ 负荷 | 准确率 | 协议失败 |
|---|---|---|---|---|
| len k2 d0 | 66 | 4 | 1.00 | 0/12 |
| len k2 d45 | 111 | 4 | 0.33 | **8/12** |
| len k2 d120 | 186 | 4 | 0.67 | 4/12 |
| cliff k3 d0 | 87 | 8 | 0.58 | 5/12 |
| cliff k4 d0 | 120 | 16 | **0.00** | **12/12** |

- **复现的一半**：负荷敏感性跨家族成立——k4（负荷16）**0.00、12/12 全协议失败**，低负荷格子有非零正确率。"2ᵏ↑→崩溃"不是 gpt-5.1 的个别脾气。
- **冒出的新麻烦（必须诚实说）**：deepseek 在**低负荷长 prompt** 上协议失败率高（k2 d45 失败 8/12）。即在 deepseek 身上，长度**确实**有副作用——但砸的是**格式遵守**（输不出可解析 ANSWER），不是**边缘化计算**。而且 d120 反比 d45 准（非单调），说明 N=12 小样本、deepseek 在干扰题上方差大。
- **含义**：deepseek 协议太脆，**长度与负荷在它身上纠缠**，不适合做"长度解耦"的干净对照。gpt-5.1 才是干净被试。

## 4. gemini-2.5-pro（跨家族·干净第二被试）：长度纯净性跨家族落地 ✅
协议稳、悬崖 k6、24k 预算。**全程 0 协议失败**（不像 deepseek）→ 是做长度解耦的干净被试。
| 格子 | prompt 词数 | 2ᵏ 负荷 | 准确率 | 协议失败 |
|---|---|---|---|---|
| 定长 k2 d0 | 66 | 4 | **1.00** | 0/8 |
| 定长 k2 d120 | 186 | 4 | **1.00** | 0/8 |
| **杀手 k2 d240（最长，低负荷）** | **306** | 4 | **1.00** | 0/8 |
| 负荷 k5 d0 | 177 | 32 | 0.75 | 0/8 |
| **杀手 k6 d0（更短，高负荷）** | 282 | 64 | **0.12** | 0/8 |

**读法**：① 定长扫描——prompt 66→**306 词**（远超 gpt-5.1 的 186）、负荷锁死=4，准确率恒 **1.00**。② 负荷扫描——4→32→64，准确率 1.00→0.75→0.12。③ **杀手对照——306 词（最长）满分，282 词（更短）崩到 0.12**。长度反转幅度比 gpt-5.1 更大（306 vs 282 词、负荷 4 vs 64），cliff 照崩。**跨家族的"长度纯净性"干净落地，且 0 协议失败——比 gpt-5.1 那一刀更狠。**

## 4b. claude-opus-4-8（跨家族·干净第三被试，最强基座）：最强一刀 ✅
claude 悬崖在 k7（最强基座），全程 0 协议失败（k7 除外）。
| 格子 | prompt 词数 | 2ᵏ 负荷 | 准确率 | 协议失败 |
|---|---|---|---|---|
| 定长 k2 d0 | 66 | 4 | **1.00** | 0/8 |
| 定长 k2 d200 | 266 | 4 | **1.00** | 0/8 |
| **杀手 k2 d440（全研究最长）** | **506** | 4 | **1.00** | 0/8 |
| 负荷 k6 d0 | 282 | 64 | 0.88 | 0/8 |
| **杀手 k7 d0（更短，高负荷）** | 483 | 128 | **0.12** | 4/8 |

**读法**：定长扫描 66→**506 词**（全研究最长）负荷锁死4 恒 **1.00**；杀手对照 **506 词满分 vs 483 词崩到 0.12**（负荷 4 vs 128，反转幅度最大）。claude k6=0.88 不崩，符合 NOTE-017 悬崖 k7。**这是迄今最强一刀——最长的 prompt 反而满分。**

## 5. 结论（四家族，不overclaim）
1. **长度纯净性跨三个干净家族成立**：gpt-5.1（186 词满分 vs 177 词崩）+ gemini（306 vs 282，0 协议失败）+ claude（**506 vs 483**，最强一刀）。每个家族里，长度被控制甚至反转，悬崖照崩——崩溃跟 2ᵏ，不跟 token 长度。外审最尖锐攻击全线闭合。
2. **负荷敏感性四家族成立**：deepseek k4 全崩、gpt k5、gemini k6、claude k7，均复现能力分级悬崖。
3. **deepseek 协议脆弱**是**不同家族的不同失效模式**（格式崩溃 ≠ 边缘化崩溃），单列为诚实附注，不削弱主结论。

## 6. 工程教训（写给未来的自己）
本实验前期"卡死"**不是进程管理问题**，而是**算法爆炸**：引擎对孤立干扰变量做了全联合枚举 2^(k+d)，d=25→2²⁵、d=45→永不返回（`STAT=R` 烧 CPU 23 分钟）。真值与 D 无关 → 在**剪枝子图**（仅 k 个混杂+X+Y）上算，精确等价（机证 4/4 match），d=45 从"永不"→ 0.001s。**诊断纪律**：遇"卡死"先用 `ps STAT` 分清是进程睡眠(S)还是 CPU 爆炸(R)，再动手——别反复 kill。
