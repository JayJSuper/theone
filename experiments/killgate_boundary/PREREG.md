# PREREG · 任务五 · 第二命门边界扫描(规模 × 对手强度)

**冻结时刻**: 本文件 SHA256 在任何结果落地前记录于 run.py 顶部;判据冻结后不改。

## 目的
测清"认知层 vs LLM"优势(净增益)随两个轴的变化曲线,找出护城河**最宽**与**塌零**的条件。
**任何格子是 0、负、优势消失,都是合格结果**——它在标出生态位边界。

## 关键可行性约束(实测,决定规模轴)
引擎 `query_intervention` 用全 2ⁿ 枚举:6节点1ms · 12节点58ms · 16节点1.3s · **20节点>20s超时** · 30节点超时。
→ **规模轴上限 = 16 节点**。JK 要的 20/30 节点:**引擎自身无法在合理时间算出 truth**,
   故这些格子如实标【N/A·引擎枚举不可行】——这是护城河的硬尺寸天花板,本身是结果。

## 两个轴
- **规模轴**: 6 / 12 / 16 节点(gen_dag,种子复现)。每尺寸固定一批 N=24 实例(冻结种子)。
- **对手强度轴**(同一裸 gpt-5.1):
  - `bare`: 单发直接答(raw)
  - `sc5`: 自洽 K=5,直接推理取中位数
  - `sc15`: 自洽 K=15,直接推理取中位数
  - `sc_tools`: 自洽 K=5 + 允许工具调用(写 Python 隔离执行),取中位数

## 三臂与评分
- C = 引擎精确(结构化输入,确定性,= truth → acc 1.0,见任务六对此"完美解析"便宜的端到端拆解)。
- 每格: acc(对手) 在 N 实例上,AM-007,TOL=0.005,协议失败=错。
- **每格净增益 = acc(C) − acc(对手) = 1.0 − acc(对手)**;**McNemar**(C vs 对手)报 p。

## 输出
一张 3(规模)× 4(对手)表:每格 净增益 + McNemar p + 对手 acc。
回答: 护城河在 (小规模? 大规模?) × (弱对手? 强对手?) 哪个角最宽、哪个角塌 0。

## 诚实范围(预声明)
- 题域 = ≤16 节点合成 SCM do 查询;**引擎精确性本身有 ~16 节点枚举天花板**。
- C 的 acc=1.0 吃"结构化输入"便宜,端到端真相见任务六。
- 成本: N=24 × 3 尺寸 × (1+5+15+~10) ≈ 2200 次 gpt-5.1 调用,8 路并行。
